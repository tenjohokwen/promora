## 5. Notes and Observations

### Note 1: updateUserInformation Does Not Publish Event

**Location:** `/Users/mokwen/dev/gitrepos/bluegithub/promora/src/main/java/com/softropic/promora/security/service/UserProfileService.java` lines 53-64

**Observation:** The `updateUserInformation()` method (for first name, last name, title, gender, nationalId, langKey) does NOT publish an `AccountChangeEvent`.

**Analysis:** This appears to be intentional. Personal info changes (name, title, etc.) are not security-sensitive like password, email, or 2FA changes. The current behavior:
- Password/email/2FA changes: Audit logged + Email notification (security-critical)
- Address/phone changes: Audit logged + Email notification (contact info changes)
- Personal info changes: No audit/notification (non-sensitive profile data)

**Recommendation:** If business requirements change to require audit/notification for personal info updates, an `INFO_CHANGED` action would need to be added to `AccountChangeEvent.Action` enum and event publishing added to `updateUserInformation()`.

### Note 2: ChangeEmailDto Location

The `ChangeEmailDto` is located in `/Users/mokwen/dev/gitrepos/bluegithub/promora/src/main/java/com/softropic/promora/security/api/ChangeEmailDto.java` (api package), not in the `api/dto/` subpackage with the new DTOs. This is a pre-existing DTO that was not moved during Phase 9. Not a functional issue, but noted for consistency.
