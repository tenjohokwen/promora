Investigate and fix the issue where address update doesn't reflect when user had no prior address.

**Root cause analysis:**
The `@updated` event in UpdateAddressDialog calls `loadProfile()` which reloads the profile from API. If this isn't working, the issue is likely:
1. The API response doesn't include the new address (backend issue)
2. The `profile.value.address` computed reference isn't updating reactively
3. The `formattedAddress` computed isn't triggering recalculation

**Most likely fix - ensure ProfilePage properly handles address prop update:**

Check if the issue is with how `UpdateAddressDialog` receives and tracks `currentAddress` prop vs what profile shows after update.

**In ProfilePage.vue:**
After `loadProfile()` completes, the `profile.value` should contain the updated address. The `formattedAddress` computed should react to `profile.value.address` changes.

Potential fix: Force the component to re-evaluate by ensuring loadProfile properly awaits:
```javascript
async function loadProfile() {
  isLoading.value = true;
  clearError();
  try {
    const data = await profileApi.getProfile();
    profile.value = data;  // Ensure we're setting the full object, not merging
  } catch (err) {
    setError(err);
  } finally {
    isLoading.value = false;
  }
}
```

**Debug steps if needed:**
1. Add console.log in loadProfile to verify API returns address
2. Add console.log in formattedAddress computed to verify it recalculates

**In UpdateAddressDialog.vue:**
The dialog emits 'updated' after successful save. Verify this is happening:
```javascript

close();
```

If the issue persists, it may be the API not returning address data for users who previously had null address. This would be a backend fix (Phase 9), but verify frontend handles it correctly by ensuring:
1. `profile.value.address` can be `null` initially
2. After update, `profile.value.address` receives the new address object
3. `formattedAddress` computed handles the transition from null to object
